# Style brief template

Copy this file next to a large document and fill it in before anyone edits. Every
writer, new reader and reviewer gets the same brief, so the document comes back in
one style. Keep it to about one page.

## What the document is and who reads it

Say in two sentences what the document is for. Then list each kind of reader with
what they do with it:

- Reader 1: who they are, and what they will reuse or decide from it.
- Reader 2: who they are, and what they will reuse or decide from it.

State the goal in the owner's own words.

## Hard rules

No editor breaks the rules in this list:

- What must not change: facts, numbers, ids, dates, names, link targets, headings.
- Voice: neutral, first person singular or academic.
- Punctuation and layout rules that a checker enforces.
- How a figure from test data is marked.
- What to do when a fix needs a fact the document doesn't have: leave the text and
  report it as "needs the owner".

## Decisions the owner already made

List each decision here. Editors don't undo or reopen one:

- Decision, with the wording to use.

## One name for one thing

List the name to use for each thing and the names to stop using. Save the same
list as a terms file for `--terms`, one line per thing:

```
name to use: other name, other name
```

## How sentences should read

Keep the rules that matter most for this document, such as:

- Lead with the point. One idea per sentence.
- Define a term at its first use in each section.
- Name the table, section or figure. Don't point at it by place.
- Give the list or the count. Don't write a vague amount.

## Phrasing to remove

List the tells this document has, with one example of each from its own text.

## Before and after, from this document

Give four to six real pairs. They calibrate an editor better than the rules do.

- Before: a sentence from the document.
  After: the same sentence as it should read.

## Where the rules live

Give the paths to the document's own checker, the house rules and the review
findings.
